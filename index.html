Introduction

Sizzle is an iPhone app I built for my senior capstone. The idea is simple: picking what to cook should be as easy as swiping. You see one recipe at a time and swipe right to save it or left to skip it.

The problem I wanted to solve is that most recipe apps make you search through hundreds of results, which gets overwhelming. After you find something, you still have to plan your meals and write a grocery list somewhere else. My goal was to build one app that covers the whole process: finding a recipe, saving it, planning the week, making a grocery list and cooking it.

Background & Motivation

Apps like Yummly, Tasty and Mealime mostly use search and scroll. That works if you already know what you want to make, but most of the time I didn't, and scrolling through a huge list gave me decision fatigue. Swiping works well for quick yes/no choices because you only look at one thing at a time. I couldn't find a recipe app that used swiping and also handled meal planning and grocery lists.

I also cook for myself and was constantly switching between a recipe website, my notes app and a grocery list. Building Sizzle was a way to fix that for myself while learning iOS development. For the class requirement to include AI, I used Claude to clean up grocery lists.

Methodology / Approach

I built Sizzle as a native iOS app in Swift and SwiftUI, using the MVVM (Model-View-ViewModel) pattern to keep the code organized. I tried to stick to Apple's built-in frameworks and ended up not using any third-party libraries.

Tools and Technologies

  • Language/UI: Swift, SwiftUI
  • Architecture: MVVM with async/await
  • Storage: Core Data (saved recipes, collections, ratings, meal plans)
  • Recipe data: Spoonacular API
  • AI: Claude API by Anthropic (grocery list cleanup)
  • Security: iOS Keychain for storing the API key
  • Other: Xcode, Git and GitHub

System Architecture

The app follows MVVM, so each part has one job:

  • Views (SwiftUI): the screens the user sees, including Onboarding, Discover, Saved, Collections, Grocery, Planner, Cooking Mode and Settings.
  • ViewModels: handle the logic for each screen, like loading the swipe deck, searching and rating saved recipes, building the grocery list and managing the meal plan.
  • Models: the app's data types, such as Recipe (from the API) and SavedRecipe (stored in Core Data), plus collections, meal plan entries and grocery items.
  • Services: do the actual work behind the scenes:
    • Recipe API Service, which gets recipes from Spoonacular
    • Grocery AI Service, which sends ingredients to Claude to clean up the grocery list
    • Persistence Controller, which saves everything with Core Data
    • Keychain Helper, which stores the API key securely in the iOS Keychain

Development Process

  1. Swipe interface (Spring 2026): built the card stack with drag gestures, connected the Spoonacular API and set up saved recipes in Core Data.
  2. Organizing recipes: added the recipe detail page, cooking mode, collections and onboarding.
  3. Planning and shopping: added the AI grocery list, the weekly meal planner, importing recipes from a URL and the settings page.
  4. Refining (Fall 2026, COMP/IT 499): reworked the rating system, tuned the AI prompt for the grocery list, and tested the app.

How the AI grocery list works

You pick the recipes you want to make, and the app combines all of their ingredients and sends them to Claude. Claude removes the measurements, merges duplicates (for example "2 cloves garlic, minced" and "1 tbsp garlic, chopped" just become "Garlic") and sends back a clean checklist.

Discussion & Future Work

What I learned

  • How to organize a bigger SwiftUI app with MVVM so features don't get tangled together
  • Core Data concurrency and migrating the data model as I added features
  • How to write and tune prompts so an AI gives back consistent, usable output

Limitations

  • The free Spoonacular plan only allows 150 requests a day, so I had to cache results
  • The AI grocery list needs an API key and an internet connection
  • It only works on iPhone and doesn't sync between devices

Future Work

  • Recommend recipes based on what you've swiped on
  • iCloud sync so it works across devices
  • Nutrition tracking and suggestions based on what's in your pantry
  • Release a TestFlight beta and eventually put it on the App Store
